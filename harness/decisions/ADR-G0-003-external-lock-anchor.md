# ADR-G0-003: Re-freeze the all-gate verifier identity with an external adjudication anchor

Status: approved for implementation; G0 acceptance remains blocked until an independent protected adjudication receipt exists

## Context

ADR-G0-002 originally retained `phase-contract.lock` unchanged while adding real TV-011 and TV-012 checkers. Review established that this cannot provide a frozen checker identity: the existing lock freezes only `harness/scripts/verify_truth.py`, and it neither identifies nor verifies the new checker code.

Changing `verify_truth.py` would invalidate its frozen SHA256 in all 207 existing gates. The root bootstrap contract remains immutable and does not prescribe implementation checker paths. The user selected re-freezing the lock rather than accepting receipt-only checker evidence.

A repository-local candidate lock, checker manifest, and verifier still are not an independent trust anchor: a single writer could alter all three consistently. A PASS must therefore require a cryptographically verifiable independent adjudication that binds their bytes before a cryptographically identifiable supervisor executes the verifier. Until a trusted issuer key, signature verification path, and supervisor attestation are provisioned outside the implementation writer's authority, every formal qualification remains `BLOCKED`.

## Decision

Keep these files byte-identical:

- `D:\科研软件制作\开发指导.bootstrap.json`
- `开发指导.md`
- `harness/scripts/verify_truth.py`

The authoritative qualification entrypoint becomes a newly frozen all-gate wrapper:

1. `harness/checker-manifest.json` lists the complete repository-local verification closure: verifier, checkers, direct and transitive local imports, executed command entrypoints, configuration, and test oracle files. Each entry has a repository-relative path, unique role, and SHA256. The manifest includes `canonical_sha256`, calculated over canonical JSON with that field omitted. Manifest paths must be non-empty regular files under the repository root and may not escape through absolute, dot-segment, or symlink paths. A local import resolved outside this declared closure is `BLOCKED`.
2. `harness/scripts/verify_frozen_gate.py` is the sole authoritative verifier for all 207 new lock gates. Before delegating, it verifies the lock's canonical integrity hash, the current lock file SHA256, its own frozen runner SHA256, the frozen checker-manifest byte SHA256, the manifest self-hash, and each required role's current file hash. It then calls the unchanged `verify_truth.verify_gate()` to preserve its existing report/artifact checks.
3. `bootstrap_contract.instantiate_lock` regenerates `phase-contract.lock` at schema `1.1`. Every one of the 207 gate runners is `verify_frozen_gate.py`; each gate carries `implementation.checker_manifest` and its required `checker_roles`. G0 roles freeze the complete closure, including `verify_truth`, `bootstrap_contract`, `task_boundary`, `source_provenance`, `g0_runner`, `supervisor_receipt`, `journal`, and `verify_frozen_gate`. Non-G0 gates freeze the shared wrapper, manifest, and unchanged `verify_truth`; a later phase must add and re-freeze its own actual checker roles before qualification.
4. Lock integrity is `integrity.canonical_sha256`, calculated over canonical JSON with the `integrity` field omitted. `validate_lock` rejects absent or mismatched integrity, runner identities other than the wrapper, manifest identity mismatch, unknown/duplicate roles, escaped paths, non-positive thresholds, or any changed requirement mapping/coverage.
5. Each report has a strict canonical schema containing its own canonical hash, `gate_id`, requirement hash, lock SHA256, checker-manifest SHA256, artifact-manifest SHA256, implementation-receipt SHA256, and adjudication receipt SHA256. The wrapper verifies all fields bidirectionally against the candidate lock, manifests, artifact bytes, execution receipt, and adjudication receipt. Missing lock/manifest/report bindings return `STALE`; missing or invalid adjudication/supervisor identity returns `BLOCKED`; current artifact mismatch returns `FAIL`; checker or runner disk drift returns `STALE`.
6. The independent adjudication receipt must be a protected signed schema, not an identity string: it declares `schema_version`, receipt ID, issuer key ID, public-key algorithm, canonical unsigned bytes, signature, decision enum, issued-at time, expiry, revocation reference, reviewer scope hash, candidate lock **raw-byte** SHA256, checker-manifest **raw-byte** SHA256, wrapper **raw-byte** SHA256, bootstrap SHA256, and reviewer permissions. `verify_frozen_gate.py` uses an allowlisted protected issuer public-key fingerprint held outside the implementation writer's authority, verifies signature, expiry, revocation status, ACL, and every bound hash. The receipt's scope hash is a canonical source snapshot/qualification-bundle hash, not a free-form path list. Receipt path ACL is an additional operating control, not proof of issuer identity. A local file generated by the implementation writer is not an independent anchor. Failure to read the issuer key, absent fingerprint provisioning, unsupported signature algorithm, unverifiable clock, unavailable or untrusted revocation responder, expired OCSP/CRL data, or any invalid signature is `BLOCKED`. An offline signed revocation snapshot is the only permitted offline substitute and must itself carry a trusted issuer signature, version, raw-byte hash, and unexpired validity window; absent such a snapshot is `BLOCKED`.
7. The supervisor execution receipt must identify the supervisor binary/entrypoint hash, command, cwd, child PID, start/finish time, exit code, stdout/stderr/artifact hashes, and a signature verifiable against a protected supervisor issuer key. The wrapper accepts PASS only when this receipt proves it launched the exact wrapper against the exact protected adjudication and candidate inputs. A direct local wrapper invocation, unrecognized supervisor, missing receipt, or inaccessible protected receipt returns `BLOCKED`.
The authoritative acceptance boundary is the protected coordinator/supervisor path, not the local journal alone. `events.jsonl` remains an audit projection, not an authorization source. The coordinator may append `accepted` only after the wrapper PASS and after validating the signed adjudication and supervisor receipt hashes; the event includes both receipt hashes and the exact bundle/report hash. It is rejected for an illegal state transition, absent receipt bindings, duplicate idempotency key, or journal chain/projection mismatch. The append capability and qualification publisher are write-restricted to the protected coordinator identity. A direct call to the unchanged verifier or a hand-written `accepted` event has no qualification authority.

8. The protected trust bundle is an external, allowlisted artifact at a fixed absolute path whose exact raw-byte SHA256 and schema version are provisioned outside the implementation writer's authority. It binds the trust root, issuer key IDs, public-key fingerprints, permitted signature algorithms, key-rotation and revocation authority, authorized receipt scopes, and domain-separation labels. An issuer key is not trusted merely because an `issuer_key_id` appears in a receipt. The trust bundle itself must be signed by the provisioned root, and any unavailable, expired, revoked, ambiguous, or unauthorized key mapping is `BLOCKED`.

9. Revocation status has a versioned signed response schema containing issuer chain, subject/key ID, status, issued-at, next-update, freshness/max-age, and response raw-byte SHA256. Unknown status, `none`, stale response, unverifiable clock, timeout, network failure, unsupported response signature, or untrusted responder is `BLOCKED`. An offline revocation snapshot is accepted only when its signed version, raw-byte hash, validity window, and binding to the adjudication receipt all match the protected trust bundle; no unsigned or unbound snapshot is an offline fallback.

10. The signed adjudication covers either each gate or one immutable qualification bundle. A per-gate signature binds `gate_id`, requirement SHA256, report canonical SHA256, implementation-receipt SHA256, recursive artifact-manifest SHA256, lock raw-byte SHA256, manifest raw-byte SHA256, wrapper raw-byte SHA256, and bootstrap SHA256. A bundle signature instead binds a canonical bundle manifest that recursively contains all 207 gate reports, receipts, and artifact manifests; the wrapper proves the current gate is a member. Canonical JSON uses UTF-8, sorted object keys, no insignificant whitespace, and arrays sorted by normalized `/` path; every leaf includes its exact repository-relative path and raw-byte SHA256. The bundle includes the interpreter/launcher and runtime hashes, configuration/oracle inputs, ACL receipt, revocation snapshot, supervisor receipt, and all execution inputs/outputs. Missing, duplicate, extra, or non-matching members are `BLOCKED`.

11. The wrapper runs with a controlled interpreter, immutable execution snapshot, controlled `sys.path`, and executable allowlist. The closure schema enumerates relative/absolute imports, namespace packages, standard-library and third-party packages, native DLLs, launcher/interpreter, environment variables, cwd, dynamic imports, generated code, `eval`/`exec`, subprocess argv and indirect entrypoints. Undeclared repository-local imports, dynamic code loads, subprocesses, configuration/oracle readers, or interpreter/launcher identities are rejected. The wrapper revalidates bound bytes immediately before delegation to prevent check/use drift.

12. Candidate lock validation compares every gate, field by field, against deterministic re-instantiation from the immutable bootstrap and signed manifest: requirement ID/hash, assurance class, `required_for`, oracle, threshold, command argv, runner path/hash, manifest path/hash, and ordered role set. The old lock raw-byte SHA256 is recorded before replacement. Candidate-to-authoritative replacement is an atomic coordinator operation: readers see either the old lock or the fully verified new lock, never a partial file. All 207 gate IDs occur exactly once; missing, duplicate, extra, or non-G0 gates retaining an undeclared old runner are `BLOCKED`.

13. The supervisor execution receipt must identify the one allowlisted supervisor entrypoint and binary hash, parent/child relationship, complete child tree, PID, command argv, cwd, interpreter hash, start/finish time, timeout/termination result, stdout/stderr and artifact hashes, and a signature by a provisioned supervisor key whose authorized scope is distinct from the adjudication issuer. Direct wrapper invocation, unrecognized launcher, incomplete child tree, PID mismatch, timeout without a signed termination result, or receipt signer mismatch is `BLOCKED`.

14. The coordinator identity, append API, and qualification publisher are protected by ACL and an allowlisted signed coordinator key. The journal write is atomic and serialized with an exclusive lock; replay, duplicate idempotency key, rollback, concurrent sequence race, illegal state transition, missing all-207 PASS, or missing bundle/receipt hashes is rejected. `events.jsonl` remains an audit projection and cannot itself authorize acceptance.

9. The signed adjudication covers either each gate or one immutable qualification bundle. A per-gate signature binds `gate_id`, requirement SHA256, report canonical SHA256, implementation-receipt SHA256, recursive artifact-manifest SHA256, lock raw-byte SHA256, manifest raw-byte SHA256, wrapper raw-byte SHA256, and bootstrap SHA256. A bundle signature instead binds a canonical bundle manifest that recursively contains all 207 gate reports, receipts, and artifact manifests; the wrapper proves the current gate is a member. Canonical JSON uses UTF-8, sorted object keys, no insignificant whitespace, and arrays sorted by normalized `/` path; every leaf includes its exact repository-relative path and raw-byte SHA256. The bundle includes the interpreter/launcher and runtime hashes, configuration/oracle inputs, ACL receipt, revocation snapshot, supervisor receipt, and all execution inputs/outputs. Missing or non-matching fields are `BLOCKED`.
10. The wrapper runs with a controlled interpreter, immutable execution snapshot, controlled `sys.path`, and executable allowlist. It rejects undeclared repository-local imports, dynamic code loads, subprocess entrypoints, configuration/oracle readers, or interpreter/launcher identities not frozen by the signed closure. It revalidates bound bytes immediately before delegation to prevent check/use drift.
11. Candidate lock validation compares every gate, field by field, against deterministic re-instantiation from the immutable bootstrap and signed manifest: requirement ID/hash, assurance class, `required_for`, oracle, threshold, command argv, runner path/hash, manifest path/hash, and ordered role set. Coverage-only equality is insufficient.
12. The acceptance authority rejects every accepted assertion that lacks the signed wrapper/supervisor receipts and exact lock/manifest bindings. The unchanged historical verifier may still execute locally, but its output has no qualification authority under the re-frozen contract.

Report canonical hashes use the same deterministic encoding: `report_canonical_sha256` is the SHA256 of canonical report JSON with `report_canonical_sha256` omitted. `manifest.canonical_sha256`, `lock.integrity.canonical_sha256`, and bundle hashes use the analogous field-omission rule. The lock, manifest, report, and receipts are all resolved from one exact protected candidate-root snapshot; any path disagreement or check/use drift is `BLOCKED`.

The old lock SHA256 must be recorded before replacement. Re-freezing invalidates all previous qualification assertions. The coordinator records them as `STALE`; the old `verify_truth.py` plus old lock combination is historical material only and is not an authorized qualification entrypoint. No prior G0 report or historical release log can be reused as accepted evidence. G0 may be re-evaluated only against the new lock and external anchor.

## Consequences

The G0 repair has two distinct outcomes:

- Engineering work can implement and test the all-gate wrapper, manifest, real tamper checks, supervisor receipt format, ACL protection, and recovery evidence.
- Formal G0 engineering acceptance remains `BLOCKED` until an independent protected adjudication anchor is supplied and the new wrapper accepts a fresh run.

This decision does not alter G1 product behavior, quality thresholds, root requirements, or the bytes of `verify_truth.py`. It replaces the qualification execution contract for all 207 gates, so old reports are stale under the only authoritative new path. It prevents receipt-only or self-authored evidence from being represented as a frozen trusted gate.
